# Simple O(n) | MySQL | LEFT JOIN

## Intuition

We need to find employees whose bonus is **less than 1000** or who **do not have a bonus**.

The `employee` table contains employee information, while the `bonus` table contains bonus information.

Since some employees may not have a corresponding record in the `bonus` table, we use a **LEFT JOIN** to keep all employees.

---

## Approach

1. Start with the `employee` table.
2. Use a `LEFT JOIN` with the `bonus` table:

   ```sql
   LEFT JOIN bonus b ON e.empId = b.empId
   ```
3. Select:

   * Employee name
   * Bonus amount
4. Filter the results where:

   * Bonus is less than `1000`, or
   * Bonus is `NULL` because the employee has no bonus record.

The condition is:

```sql
WHERE bonus < 1000 OR bonus IS NULL
```

---

## Example

Suppose the tables contain:

### Employee

| empId | name |
| ----: | ---- |
|     1 | John |
|     2 | Dan  |
|     3 | Brad |

### Bonus

| empId | bonus |
| ----: | ----: |
|     1 |   500 |
|     2 |  1500 |

After the `LEFT JOIN`:

| name | bonus |
| ---- | ----: |
| John |   500 |
| Dan  |  1500 |
| Brad |  NULL |

Now apply:

```sql
bonus < 1000 OR bonus IS NULL
```

Results:

| name | bonus |
| ---- | ----: |
| John |   500 |
| Brad |  NULL |

---

## Complexity

* Time complexity:

$$O(n)$$

The database performs a join and filtering operation. The exact execution cost depends on indexes and the query optimizer.

* Space complexity:

$$O(n)$$

The database may use additional internal space to perform the join.

---

## Code

```mysql
# Write your MySQL query statement below

SELECT 
    e.name,
    b.bonus
FROM employee e
LEFT JOIN bonus b
    ON e.empId = b.empId
WHERE b.bonus < 1000 
   OR b.bonus IS NULL;
```

---

## Key Takeaways

* Use `LEFT JOIN` when employees without a bonus record must also be included.
* `NULL` must be checked using:

  ```sql
  IS NULL
  ```

  rather than:

  ```sql
  = NULL
  ```
* The `WHERE` condition keeps bonuses below `1000` and employees with no bonus.
* Prefixing `bonus` with `b.` makes it clear that the column comes from the `bonus` table.
